## Бизнес-домен

Моделируется система сбора и предобработки экзаменационных работ для обучения ИИ-ассистента проверки развёрнутых ответов. Вуз, школа и колледж передают задачи подготовки работ. Вычислительные серверы выполняют OCR, проверку качества изображения, анонимизацию и нормализацию текста. Результатом обслуживания является обезличенный обучающий пример.

Отказ означает исключение задачи подготовки из текущего обучающего набора. Оригинал экзаменационной работы сохраняется. Оценивание студентов не входит в моделируемый процесс.

## Взаимодействие компонентов

Используется классическая архитектура: каждая заявка сначала поступает в буфер. `InsertionDispatcher` имеет ссылку на `CircularBuffer` и не обращается к серверам. `SelectionDispatcher` работает с буфером, `ServerPool` и текущим `ProcessingPackage`.

`ServerPool.lowestFree()` возвращает конкретный свободный `ComputingServer` с минимальным номером. `start(request, packageId, t)` вызывается на этом сервере. Позже календарное событие адресует `finish(t)` тому же серверу. Пул не запускает обработку и не принимает решения об отказе.

`SelectionDispatcher.assignNext(t)` возвращает одно назначение либо отсутствие назначения. `SimulationEngine` повторяет вызов, пока назначения доступны. После каждого назначения движок учитывает начало обслуживания, добавляет событие завершения в календарь и сохраняет состояние. Все методы записи `StatisticsCollector` вызываются движком.

## Кольцевой буфер и отказы

Поиск свободного места начинается с указателя `p`. Если найдена ячейка `j`, в неё записывается новая заявка, после чего `p = (j + 1) mod capacity`. Остальные заявки не перемещаются. При полном буфере вытесняется заявка в ячейке `p`; новая занимает её место, указатель также переходит к следующей ячейке.

При назначении на сервер заявка извлекается из буфера. Ячейка освобождается без изменения указателя постановки. Поэтому работающие заявки не могут быть вытеснены: в буфере находятся только ожидающие заявки активного либо будущих пакетов. Отказ учитывается за источником вытесненной заявки один раз.

## Фиксированный пакет

Пакет формируется при наличии свободного сервера и отсутствии активного пакета. Выбирается наиболее приоритетный источник среди представленных в буфере. Все его ожидающие заявки на момент выбора входят в `frozenIds`. Идентификатор пакета выдаёт диспетчер выбора.

Участники остаются в буфере до назначения. `nextWaiting()` возвращает только участника со статусом `WAITING`. Состояния `RUNNING`, `SERVED` и `REFUSED` пропускаются. Новые заявки, включая заявки того же источника, не добавляются в действующий пакет.

Все серверы обслуживают один активный пакет. Если ожидающих участников больше нет, но хотя бы один ещё обрабатывается, свободные серверы простаивают. Следующий пакет создаётся только после завершения всех обслуживаемых участников и отсутствия ожидающих участников предыдущего пакета.

### Принятые проектные решения

- Внутри пакета используется FIFO по времени поступления, затем по порядковому номеру заявки источника.
- Вытесненный ожидающий участник сохраняется в неизменном составе со статусом `REFUSED`. Это терминальный исход участия с отказом. Условие закрытия: каждый участник имеет `SERVED` либо `REFUSED`. Таким образом, отказанная заявка не блокирует завершение пакета и не заменяется новой в его составе.
- При одинаковом модельном времени сначала обрабатываются все завершения по номеру сервера, затем все поступления по номеру источника и заявки, после этого выполняются назначения. Это определяет однозначный порядок событий.
- При поступлении проверяется возможность обслуживания изначально свободным сервером. Длительности диспетчерских действий отдельно не вводятся.

## Статистика и пошаговый режим

Журнал содержит поступления, вставки, вытеснения, назначения и завершения. В ОД2 сохраняются состояния после генерации, вставки с обработкой возможного отказа, планирования следующего поступления, каждого назначения и каждого завершения. Отдельно фиксируется состояние после завершения цикла назначений, включая закрытие пакета и простой серверов.

Снимок включает модельное время, источники, ячейки буфера, указатель, состав и состояния пакета, серверы, календарь и текущие показатели. События текущего времени, уже извлечённые из календаря и ещё не обработанные, сохраняются в `remainingCurrentEvents`.

В ОР1 выводятся количества поступивших, начавших обслуживание, обслуженных и отказанных заявок, доля отказов, среднее время ожидания начавших обслуживание, среднее время пребывания обслуженных заявок и загрузка каждого сервера. При отсутствии наблюдений соответствующее среднее или доля не определены. Визуальная временная диаграмма не требуется согласно памятке преподавателя.
